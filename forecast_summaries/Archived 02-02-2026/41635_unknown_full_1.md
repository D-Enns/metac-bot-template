**Bringing A2UI to Google Workspace with Gemini**
This article details the implementation of the Agent-to-User Interface (A2UI) protocol within Google Apps Script (GAS), enabling AI-driven, dynamic, and secure user interfaces directly inside Google Sheets. The system uses Gemini’s structured output to generate A2UI-compliant JSON, which is rendered natively in a Google Sheets dialog via a serverless architecture. The workflow begins with a user entering a natural language request (e.g., 'Find 3 Chinese restaurants in New York'), which is sent to the GAS backend using google.script.run. The backend routes the request to the Gemini API via a system prompt, which acts as a router to determine the appropriate sub-application (e.g., Restaurant Finder or Event Manager). Tools are executed locally—such as querying data from the spreadsheet or checking Google Calendar—before the results are returned to Gemini, which generates a structured A2UI JSON response. This JSON is then parsed and rendered in real time by a JavaScript engine within the dialog, producing interactive UIs like forms, image-rich lists, and event selectors. Unlike the standard distributed A2UI model relying on external A2A servers, this GAS-native version operates entirely within Google’s internal network, eliminating latency and external infrastructure. The approach offers zero setup cost, seamless Google Workspace integration (e.g., Sheets, Calendar), high performance, and enhanced security through schema-based rendering. However, it requires manual rendering logic and is limited by GAS execution quotas (e.g., 6-minute timeout). The implementation has been demonstrated with two prompts: one retrieving mock restaurant data with booking forms, and another fetching events from a spreadsheet and syncing them to Google Calendar. The project confirms that A2UI can be effectively deployed in a serverless, secure, and deeply integrated manner across Google Workspace applications.
