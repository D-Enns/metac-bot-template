# Plan: Check and Integrate Metaculus Updates (03-28-2026)

## Context

The bot uses `forecasting-tools` 0.2.85 (latest is 0.2.87) and `litellm` 1.80.10 (transitive dep). On March 24, 2026, litellm versions 1.82.7 and 1.82.8 were compromised in a supply chain attack (credential-stealing malware via the TeamPCP campaign). Our installed version is safe, but the current constraints don't explicitly block the compromised versions. We should upgrade forecasting-tools and add a defensive litellm pin.

## LiteLLM Supply Chain Attack Details

On March 24, 2026, the TeamPCP group published two malicious litellm versions to PyPI:
- **1.82.7**: Malicious payload in `litellm/proxy/proxy_server.py` (executes on import)
- **1.82.8**: Added `litellm_init.pth` file that fires on every Python startup (no import needed)

**Capabilities of the malware**: Steals SSH keys, cloud credentials, Kubernetes secrets, crypto wallets, and .env files. Deploys persistent backdoors.

**Attack vector**: Attacker compromised the maintainer's PyPI credentials via a prior Trivy (security scanner) breach.

Both versions have been removed from PyPI. Our current version 1.80.10 was never affected.

## Implementation Steps

### Step 1: Edit `pyproject.toml` — add litellm exclusion pin

Add under `[tool.poetry.dependencies]`:
```toml
litellm = ">=1.59.1,!=1.82.7,!=1.82.8,<2"
```
This is defense-in-depth to prevent ever resolving to compromised versions.

### Step 2: Update poetry.lock

```bash
poetry lock --no-update          # Validate new constraint is satisfiable
poetry update forecasting-tools  # Pull 0.2.87 + compatible transitive updates
poetry show forecasting-tools    # Verify 0.2.87
poetry show litellm              # Verify NOT 1.82.7/1.82.8
```

### Step 3: Smoke-test imports

```bash
poetry run python -c "

### Step 4: Run existing tests

```

### Step 5: Run test-mode forecast (optional but recommended)
