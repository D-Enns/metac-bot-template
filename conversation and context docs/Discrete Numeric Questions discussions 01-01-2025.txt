Ben Wilson — 12/11/25, 10:33 PM (Main Metaculus Developer for AI forecasting competition)
Discrete Question Conversion
We are starting to do some conversions of should-be-discrete questions on the site (both inside and outside of AIB). There were 6 questions (1.5% of the total) that were launched as numeric in AIB, which should have been discrete (the relevant site questions were numeric since they were created before the discrete question type was available). This set is big enough that we don't want bots that made code specifically to maximize spiky distributions to get an unfair advantage  (i.e., when the interpretive meaning of the spiky distribution and the normal distribution are the same, yet one bot would get more points). We have made code that can convert these questions to discrete ones. We have moved forward with this conversion, but wanted to solicit feedback, since we can still annul. There has been at least one team that has reached out and mentioned that this conversion might be unfair, and if enough others have problems with the conversion, then we can annul these instead. If we make a mistake in the conversion process for any one question, we will default to annulling all of them (we have done testing, and don't expect this, though).

Emdash — 12/12/25, 10:58 AM
I haven't looked through the questions yet to see whether I would be helped/harmed, but definitely support this change. Given that the scores are calculated on the value of the PDF for numeric questions the old format would be (even unintentionally) super gameable. If I'm understanding the problem correctly, a uniform distribution that was 1/n on the integer values and 0 otherwise would max out the potential score for every question with less than n=20 potential values (based on a pdf max of 0.59, which I remembered as the max but didn't look it up again. For a max of 0.2 it would be n=32). Depending on when/how in the flow the pdf values are capped even a totally innocent 'spiky' distribution would get insane scores. 

To be even more of a nerd it would be more robust to take the mass (or equivalently the mean prediction) in each bin instead of the highest point, because the highest point is not really representative. If you had a bot saying the p(1) = .5 and p(2) = 0, the bin value in p(2) would be set as 0.25 because the linear line between those points pass the bin edge at 0.25 when interpolating linearly. But this quibble is super minor and practically I don't think it will matter that much. The spiky issue is much bigger.

Ben (Mantic) — 12/15/25, 2:19 AM
The pdf max is per bin so you hit the current limit of 0.59 if there's only one integer value within the range, and the new limit of 0.2 if there are 5 or fewer.

Emdash — 12/15/25, 12:34 PM
Right, thank you. I should have specified that, because the numeric input takes a CDF with 201 bins by default, those Ns I calculated were using that bin count and bin width = N/201. Since you have 1.0 cumulative probability to spend, and the bin_width <1 as long as N<201,  the 'spend' (i.e. probability mass, or the amount the CDF rises between bins) is only 0.59*bin_width. Ben (Mantic) — 12/18/25, 3:02 AM
They've already factored the /201 in the 0.59. The max "density" allowed is 201 * 0.59 = 118.59 (averaged over a bin). The 'pdf max' is actually a limit on the integral over any bin
\int_{x_i}^{x_{i+1}} p(x) dx \leq 0.59
